## 目的

`exp001` では Codex が broad EDA の notebook とログを生成した。
これは全体像を早く把握するには有用だったが、EDA はデータへの直感と後続の仮説生成に直結する。

そのため `exp002` では、baseline 作成へ進む前に、ユーザー自身がコードを書きながら House Prices のデータを納得いくまで探索する。

## 方針

- Notebook は `notebooks/exp002.ipynb` を使う。
- Codex は必要に応じて相談相手やレビュー役になるが、EDA の主なコードはユーザー自身が書く。
- きれいな分析レポートを最初から作るより、疑問を立てて、手を動かし、観察を積み上げることを優先する。
- 気づいたことは、後で仮説検証に使える形で短く記録する。
- baseline 作成、CV 設計、特徴量追加、提出作成などの定型プロセスは、この EDA の後に Codex で定型化してよい。

## ここまでに見た特徴量

### `MSSubClass`

- 建物タイプを表すカテゴリコードとして確認した。
- 件数分布は均等ではなく、`20` と `60` が多い。
- `SalePrice` の分布を見ると、`60` や `120` は比較的高め、`30`, `45`, `90`, `180` は低めに見える。
- ただし `MSSubClass` 単体の効果ではなく、面積、築年、品質などをまとめて反映している可能性がある。
- 数値コードだが順序的な意味は薄いため、モデルではカテゴリとして扱う候補。

### `MSZoning`

- 用途地域ごとの件数と `SalePrice` / `log1p(SalePrice)` の代表値を確認した。
- 通常の `SalePrice` ではカテゴリ間に大きな価格差が見える。
- `log1p(SalePrice)` で見ると差は圧縮されるが、`FV`, `RL`, `RH`, `RM`, `C (all)` のような順序は残っている。
- log 空間では、絶対額の差ではなく倍率に近い差として読めるため、RMSLE を意識した比較に向いている。
- `MSZoning` は価格帯と関係がありそうだが、`Neighborhood`, `OverallQual`, `GrLivArea` などとの関係も確認する必要がある。

### `LotFrontage`

- 道路に接している敷地間口の長さとして確認した。
- 分布は 70 前後にピークがあり、やや右に裾が長い。
- `SalePrice` / `LogSalePrice` と正の関係がありそう。
- 欠損が 259 件あり、欠損ありの方が `LogSalePrice` の中央値がやや高かった。
- 欠損は単なる記録漏れではなく、立地や区画条件を反映している可能性がある。
- 後続実験では、中央値補完だけでなく `LotFrontage_missing` フラグを残す仮説を検討したい。

### `LotArea`

- 敷地面積として確認した。
- 元の分布は強い右裾を持ち、一部の非常に大きい土地が可視化の軸を大きく歪めていた。
- 全範囲の散布図では `SalePrice` との関係が見えにくかった。
- `LotArea <= 50000` に絞ると、`SalePrice` / `LogSalePrice` と正の関係が見えやすくなった。
- 外れ値の影響が強いため、`log1p(LotArea)` や上限クリップを後続実験候補にする価値がある。

## 現時点の仮説候補

- `MSSubClass` はカテゴリ特徴量として有用そう。
- `MSZoning` は価格帯と関係がありそうだが、他の立地・品質特徴量と重なっている可能性がある。
- `LotFrontage` の欠損は情報を持つ可能性があり、欠損フラグが効くかもしれない。
- `LotArea` は正の関係を持つが外れ値の影響が強いため、log 変換やクリップで改善するかもしれない。
